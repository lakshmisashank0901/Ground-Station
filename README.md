# AI-Assisted Satellite Health Monitoring — Ground Station

Software-only / simulation-driven ground station for **SAT-01**. It has a mission-control web UI, a FastAPI
backend, a database, a hybrid ML anomaly detector (rules + Mahalanobis + Isolation Forest + LSTM with score
fusion) and a physics-based spacecraft simulator with fault injection. SAMRH/OBC hardware is deliberately
out of scope. The simulator feeds the same ingestion path a future hardware gateway will use
(see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#4-future-samrh-integration-boundary)).

```
frontend/   Next.js 15 + TypeScript + Tailwind + Recharts mission-control UI (:3000)
backend/    FastAPI + SQLAlchemy + numpy/scikit-learn (+ Keras for LSTM training) (:8000)
  app/        api · core · telemetry · ml · simulation · database · services · websocket
  training/   preprocessing · train_mahalanobis · train_isolation_forest · train_lstm · evaluate · train_all
  models/     scaler.pkl · mahalanobis.pkl · isolation_forest.pkl · lstm.keras · lstm_weights.npz · metadata.json
  datasets/   raw · cleaned · processed (generated by the simulator)
  tests/      unit · API · ML · simulation · end-to-end (pytest)
docs/       API contract, architecture/ER/ML diagrams, telemetry & scenario spec, operator guide, test plan, ML report
```

## Quick start with Docker Compose (recommended)

```bash
cp .env.example .env          # set POSTGRES_PASSWORD
docker compose up --build     # postgres + backend (models trained during the image build) + frontend
```

Open http://localhost:3000 (UI) and http://localhost:8000/docs (interactive API docs).
`docker compose --profile gateway up` also starts the standalone simulator container as an external
telemetry source. Set `POSTGRES_IMAGE=timescale/timescaledb:latest-pg16` and `TIMESCALE_ENABLED=true` to use
TimescaleDB hypertables.

## Local development (no Docker)

Backend (Python 3.10–3.12):

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pip install -r requirements-ml.txt       # optional: TensorFlow, only needed to train the LSTM
python -m training.train_all --fast      # optional: otherwise models are trained automatically at first start
uvicorn app.main:app --reload --port 8000
```

By default it uses SQLite (`backend/groundstation.db`). To use PostgreSQL, set
`DATABASE_URL=postgresql+psycopg2://user:pass@host:5432/db`. Settings are read from environment variables or
`backend/.env` (see `backend/.env.example`). The in-process simulator starts automatically
(`SIMULATOR_AUTOSTART`).

Frontend (Node 20+):

```bash
cd frontend
npm install
npm run dev        # http://localhost:3000 (NEXT_PUBLIC_API_URL defaults to http://localhost:8000)
```

If the UI is served from another origin, add it to the backend `CORS_ORIGINS`.

External telemetry source (gateway path):

```bash
cd backend && python -m app.simulation.standalone --url http://localhost:8000 --speed 5 \
    --scenario obc_thermal --at 120 [--framed]
```

## Training & evaluation

```bash
cd backend
python -m training.train_all            # full: 96k normal samples + 21 labelled fault runs per split
python -m training.evaluate             # re-evaluate saved models on fresh fault runs
python -m training.preprocessing        # just (re)generate datasets/
```

All data is simulated and split chronologically (70/15/15). The scaler is fit on the training split only.
Thresholds are calibrated on normal validation data, and fusion weights are tuned on labelled validation
fault runs. Metrics are reported on a separate test set. Model metadata (version, training date, dataset,
feature order, scaler version, thresholds, metrics, git version) is written to `models/metadata.json` and
recorded in the `model_versions` table. See [docs/ML_REPORT.md](docs/ML_REPORT.md).

## Tests

```bash
cd backend && pytest                       # 54 tests: unit, API, ML, simulation, end-to-end
cd frontend && npm test && npm run lint && npm run build
```

## Security notes

* Secrets/DB credentials come from environment variables / `.env`; `.env` is git-ignored.
* Every payload is validated (pydantic). Commands are limited to a fixed catalogue with parameter
  validation and a confirmation step, so arbitrary execution isn't possible. Every attempt, including
  rejected ones, is logged.
* Optional role-based access: `AUTH_ENABLED=true`, `API_KEYS=key1:operator,key2:viewer`. Operators can
  ingest telemetry, acknowledge/resolve, command and control the simulator. Read-only endpoints stay open
  for the dashboard.
* Logs are structured JSON. `/api/v1/health` and `/api/v1/system/status` expose backend, database, ML,
  WebSocket, simulator and telemetry-staleness health.
